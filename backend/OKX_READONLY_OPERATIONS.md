# OKX 唯讀監控：部署前檢查

目前只有可選擇啟動的獨立 worker 程式 `okx_readonly_worker.py`，**尚未部署，也不會自動執行**。

## 安全界線

- 預設拒絕啟動：必須設定 `SINKA_OKX_READONLY_MONITOR=true`。
- 僅允許 OKX 模擬模式：必須設定 `SINKA_OKX_DEMO=true`。
- API 憑證只在伺服器端取得，**不可**貼到 GitHub、GitHub Pages、聊天訊息或前端程式。
- OKX API Key 初期只授予 **Read（讀取）** 權限；不得授予 Trade 或 Withdraw。
- Firestore 的狀態紀錄是診斷資訊，**不能作為下單解鎖條件**。
- 已增加 SWAP 未完成委託分頁查詢及逐筆比對。只有空清單或與本地追蹤完全一致時，`orders_matched` 才可能為 true；這只是同步診斷，**不表示已通過模擬交易驗證，更不會解鎖真實下單**。已新增獨立 Firestore 訂單帳本，僅允許有效租約持有人修改，重啟時會讀取既有追蹤訂單；**尚未完成自動更新各種成交狀態、帳本初始化審核與端對端驗證**。未知訂單不會自動加入帳本。
- 目前 worker 僅假設本機持倉為空。帳戶若持有任何部位，必須先完成正式持倉帳本才能繼續。
- worker 使用獨立 Firestore 租約，避免一般情況下多個實例同時寫入；**不等同**獨立監控告警、可靠排程或自動交易服務。

## 部署前仍需完成

1. 驗證 GitHub Actions 所有單元測試及 Firestore emulator 測試通過。
2. 驗證交易所未完成委託分頁掃描，包括大量訂單、分頁期間變動、成交回報、持倉快照及重啟恢復流程；完成訂單帳本的成交進度自動寫回及人工恢復審核流程。
3. 建立 GCP 專案、帳務、IAM 服務帳戶及 Secret Manager，僅在伺服器環境注入 OKX 模擬帳戶唯讀憑證。
4. 確定 Cloud Run 的執行模型與排程，另設獨立健康檢查／告警。單純設定最小實例不能保證無中斷執行。
5. 在模擬交易環境完成斷線、超時、回朔、重複指令、部分成交等測試，再由使用者決定是否展開後續交易權限開發。

## 程式入口（僅供開發環境）

`python backend/okx_readonly_worker.py`

此程式需要 Firestore 和正確環境變數及伺服器端憑證；不能直接在 GitHub Pages 執行。**目前不要求使用者執行這些命令。**


## 成交與持倉對帳限制

新增 `okx_fill_position.py` 純計算模組：根據已核實的起始持倉與完整、按時間排序的成交清單，核對開倉、加倉、部分平倉和完全平倉。反轉持倉、成交清單缺漏、重複交易編號或最終張數不一致均不能通過。

**重要：** `/api/v5/trade/fills` 的近期成交視窗不能保證涵蓋所有歷史；不得直接將這類查詢結果設為 `interval_complete=True`。必須先建立並審核成交游標、水位、帳本初始化時點及完整性證據，才可用於後續交易准入。此模組目前**沒有接入自動解鎖或真實下單**。


## 成交恢復水位（新增，尚未部署）

- `okx_fill_checkpoint.py` 使用前一次成交的完整內容作為錨點；新查詢找不到錨點、同編號內容變動或重複成交，皆判定不可銜接。
- `okx_fill_watermark_store.py` 在有效 Firestore 租約下，以交易寫入尚未處理的成交與新水位；既存成交、過期 worker 或缺少初始水位會拒絕寫入。
- 初始水位必須另外以審核流程建立，目前**沒有自動建立初始水位的生產程式**，不可因為第一次抓取成功便假定歷史完整。
- 錨點重疊只代表本次取得的頁面與上次紀錄銜接；不能證明完整歷史成交、OKX 持倉已清零或具備下單資格。
- 水位核對已接入獨立 OKX 唯讀 worker：缺少初始水位、錨點缺失、交易明細與本地訂單不一致都會將本輪同步標為不健康；成功追加新成交後仍需再次執行完整同步，才可標為健康。這不是下單解鎖。worker 尚未部署，emulator、端對端與斷線測試仍待實際驗證。


## 唯讀監控已串接成交水位（待實測）

`okx_readonly_worker.py` 在持倉與未成交委託同步通過後，才執行 `okx_fill_audit.py`：要求已核對的成交初始水位、查詢近期 SWAP 成交、檢查錨點重疊與張數、並由具有效租約的 Firestore 交易寫入。缺少水位、遺失錨點、重複紀錄、張數不一致、租約過期或寫入失敗，監控狀態一律標記不健康。若新增成交成功寫入，仍須再等下一輪完整同步核對後才能回報健康。

**這是診斷流程，不表示完整成交歷史已查明，更不是交易解鎖流程。** 尚未部署、尚未接入獨立持續監控及告警，也尚未驗證實際 OKX API 回應。
