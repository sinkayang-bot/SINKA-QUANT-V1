# 未確認送單的無活動覆核

明確執行 `okx_demo_cloudshell.py --resolve-unfilled`，不會呼叫交易 worker、下單、平倉、取消或重新送出原識別碼。此流程不是拒單證明；只保存截至覆核時點未發現受理效果的證據。

只支援原帳本已有已驗證交易歸檔、單一已標記送出但 entry_status=unknown 的策略意圖；不得已有交易所訂單編號、訂單觀察、成交、平倉或緊急減倉。原送單須至少經過六十秒且在七天內。這段等待並不把未知結果推定為交易所拒單。

取得同帳戶帳本租約並保持停止進場後，先補查原基準缺少的舊成交。再於五秒內取得前後完整穩定快照、兩次原識別碼 51603/空資料，以及原基準起的雙輪完整空帳單。必須零持倉、零一般掛單、零保護掛單、完整成交集合及現金與原基準完全一致。

在單一 SQLite 交易內再次核對原意圖、租約、原交易歸檔鏈和獨立無活動歸檔鏈。原計畫、執行狀態、時鐘、風控預留、每日計數及覆核證據寫入 demo_no_effect_archive 後，才移除活動意圖與活動執行槽位。原帳本基準、交易歸檔序號、風控預留與計數不變，不產生虛構成交、損益或平倉。任何驗證／寫入失敗均保留原活動紀錄。

新歸檔永久阻止原 client ID 被重新登記；原 demo_risk_entry 也繼續保留。完成後仍停止進場，後續必須由正常啟動路徑再次核對帳戶，不會直接恢復交易。若之後發現遲到的帳戶活動，正常成交／帳單核對仍會停止流程，不採納為新交易。

正常策略送單也會保存純數字 API/code 與 sCode 到 demo_entry_response_diagnostics，並在錯誤摘要顯示；不儲存或顯示 API 金鑰、原始錯誤訊息。舊嘗試沒有保存的回應無法補推原因。
