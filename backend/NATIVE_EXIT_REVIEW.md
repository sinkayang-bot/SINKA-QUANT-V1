# 原生保護單出場唯讀查核

`okx_demo_cloudshell.py --audit-trade` 保留原帳本，先核對完整成交、帳單與現金，再使用既有 DemoCloseReader 取得五秒內兩輪穩定的原始進場單、原生 OCO 保護單與平倉子單。

只有既有嚴格 validate_lineage 通過，且進場單、平倉單與帳單查核所用資料完全一致，現金、持倉、掛單、保護單、合約與帳戶範圍仍一致，才回報 native_exit_verified=true。原生停損或停利是哪一種觸發，這個欄位不做區分。

這是額外的唯讀來源證據，不修改 automatic_exit_verified（原有的持久化緊急減倉驗證）、測試用途旗標或結算權限，不更改帳本，不歸檔，不發送交易或取消委託，不開放進場。

native_exit_stage 只顯示固定分類：bill_evidence_required、native_lineage_reads、audited_order_match、audited_snapshot_match、verified。無法驗證不能推論是人工平倉。額外查核失敗不撤銷已成功的帳單核對。

網頁與 Cloud Shell 執行器必須各自更新。重新載入網頁不會更新現有執行器；可從新程式目錄直接執行 --audit-trade，無需重啟策略。既有控制器必須保持閒置，勿同時送出其他動作。

## 原生結算與過渡期

`--close-reviewed-native` 使用原有嚴格的原生 OCO 成交、完整雙輪帳單、現金、合約及歸檔鏈驗證，原子結算並歸檔。只送出 GET，不呼叫交易 worker；必須已有原綁定及單一已派送意圖，取得帳本租約後保持禁止進場。失敗保留原意圖與帳本，不把額外的 native_exit_verified 診斷旗標當作結算授權。過期的舊基準成交使用既有雙輪歷史查詢補回，五秒內的新證據時窗不延長。

一般策略持倉已確認受保護後，若只有複合快照不一致、時間／權限／原單查詢皆一致，最多等三輪且最多十五秒，重新取得整套 GET 證據。等待期間使舊快照失效，不派新單、不取消、不平倉、不清除意圖；未穩定仍停止。強制退出不走此等待路徑。首次進場未驗證、權限錯誤、訂單異常不走此路徑。

已驗證原生出場但未滿既有五秒帳單回報時窗時，回報 native_settlement_pending；不提前寫入結算。以上行為仍需在更新執行器後實測，單元測試不等於線上驗收。

## 隔日接續的原生歷史結算

僅明確執行 `--close-reviewed-native` 才啟用 historical_close；必須先取得原帳本租約且保持 kill switch。一般交易與自動對帳仍保留原有六十秒連續核對限制。歷史模式允許最近七天內的原基準進行閉倉稽核，仍須以新取得的五秒穩定快照、嚴格原生關聯、完整雙輪帳單、原成交與現金核對在同一交易內結算歸檔。任何後續稽核失敗會回滾閉倉、損益與歸檔寫入。

歷史損益寫回原出場的台灣日曆日，不當作今天的新交易，不重設每日風控、不開放新進場。超過七天或交易所無法提供完整證據時保留帳本並停止，不調整時間戳或建立新基準。

## 真實時鐘的階段交接

原生成交稽核會在完成時寫入 last_checked。若後續結算仍使用交易開始時的較舊 now，真實時鐘前進一毫秒即可誤觸 Close fill continuity lost；固定時鐘的測試無法暴露此問題。現於原生成交稽核完成後重新取得並驗證租約時間，再交給帳單結算／歸檔。新增前進一毫秒可成功歸檔，以及前進超過五秒仍回滾的回歸測試；未重寫任何快照時間戳。

## 自然平倉後繼續掃描

已核對為空倉時只使原進場快照失效，等待原生成交與帳單原子結算；不把自然平倉誤當成停止要求。原 kill switch 不變，強制清理或停止要求仍設定停止。只有原來已啟動且未停止的策略，在結算成功取得新核對憑證後才可繼續掃描；此流程不會清除恢復模式或人工設定的停止狀態。

新增整合測試從已持倉到原生保護單出場、完整成交帳單歸檔，再到下一輪等待訊號，確認沒有送出額外平倉單。實際下一輪連續運作仍需 Cloud Shell 最新控制器的線上驗收。
